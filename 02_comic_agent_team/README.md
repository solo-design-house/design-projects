# 16컷 만화 제작 Agent 조직도

Claude는 이미지를 직접 만들지 못하므로 **이미지 생성은 Codex CLI 에이전트**가 맡는다.
각 "직원"은 역할 프롬프트를 가진 `codex exec` 실행 1회(또는 세션 1개)이고,
직원끼리는 대화하지 않고 **공유 폴더의 파일**로만 일을 주고받는다.

---

## 1. 결론 요약

| 질문 | 답 |
|---|---|
| 팀장이 필요한가? | **필요.** 단, 그림은 그리지 않고 일을 쪼개고, 상태를 기록하고, 재작업을 보내는 일만 한다. |
| 검수자가 필요한가? | **필요. 만든 사람과 다른 에이전트여야 한다.** 자기 그림을 자기가 검수하면 거의 다 통과시킨다. |
| 총 몇 명? | **권장 9명** (팀장 1 · 기획 2 · 아트 1 · 작화 2 · 마감 1 · 검수 2). 최소 5명, 확장 12명. |
| 가장 큰 위험 | ① 16컷 내내 캐릭터 얼굴·옷이 바뀌는 것 ② 이미지 모델이 한글 말풍선을 깨뜨리는 것 |
| 위험 대응 | ① 아트 디렉터가 먼저 **캐릭터 시트**를 만들고 모든 컷에 참조 이미지로 첨부 ② 대사는 그림에 넣지 않고 **식자 담당이 코드로 합성** |

## 3. 직원별 역할 정의

| # | 직원 | 인원 | 입력 | 하는 일 | 산출물 | 이미지 생성 |
|---|---|---|---|---|---|---|
| 0 | **팀장 (Director)** | 1 | 사용자 요청, `production.json` | 작업 순서 지정, 각 직원 호출, 검수 결과 보고 재작업 배정, 재시도 한도 관리, 사용자 승인 요청 | `production.json` (상태표), 작업 지시서 | ✗ |
| 1 | **시나리오 작가** | 1 | 주제·톤·대상 독자 | 로그라인 → 16컷 플롯. 기(1–4)·승(5–8)·전(9–12)·결(13–16) 4막 구조, 컷별 사건과 대사 | `script.md` | ✗ |
| 2 | **콘티 작가** | 1 | `script.md`, 스타일 바이블 | 컷마다 샷 크기, 앵글, 구도, 등장인물 위치, 표정·포즈, 배경, 말풍선 위치·여백 지정. 이미지 생성용 프롬프트 초안까지 작성 | `storyboard.json` (16개 항목) | ✗ |
| 3 | **아트 디렉터** | 1 | `script.md` | 그림체, 선, 채색, 팔레트 확정. 캐릭터별 **정면·측면·표정 시트** 생성. 배경 기준 이미지 생성. 모든 프롬프트에 고정으로 붙일 "캐릭터 고정 문구" 작성 | `bible/style.md`, `bible/char_*.png`, `bible/bg_*.png` | ✓ |
| 4 | **작화 담당 A·B** | 2 | `storyboard.json`, `bible/` | 맡은 컷을 생성. 캐릭터 시트를 반드시 참조 이미지로 첨부. **말풍선·글자는 그리지 않고** 콘티가 지정한 여백만 비워 둠 | `panels/pNN_vK.png` | ✓ |
| 5 | **식자·편집** | 1 | 통과된 컷, `storyboard.json` | 말풍선·대사·효과음을 코드(PIL/SVG)로 합성. 4×4 페이지(또는 세로 스크롤)로 조판, 칸 간격, 내보내기 | `lettered/`, `final/comic.png`, `final/comic.pdf` | ✗ (코드) |
| 6 | **연속성 검수** | 1 | 컷 이미지 + `bible/` | 얼굴·머리·옷·소품이 시트와 같은지, 앞뒤 컷의 좌우 위치(180도 규칙), 시간대·조명 일관성, 손가락 등 깨진 부분 | `review/continuity_*.json` | ✗ (이미지 보기만) |
| 7 | **연출·품질 검수** | 1 | 대본·콘티·완성본 | 대본·콘티 단계에서 이야기 흐름과 컷 수 검사. 완성본에서 읽는 순서, 말풍선이 얼굴을 가리는지, 오탈자, 마지막 컷의 펀치라인 | `review/story_*.json` | ✗ |

### 작화 담당을 2명으로 두는 이유
- 1명이면 16컷을 순서대로 그려 느리다.
- 4명 이상이면 사람마다 그림체가 벌어지고 API 동시 호출 한도에 걸리기 쉽다.
- **막 단위(1–8 / 9–16)로 나누면** 같은 장면의 연속 컷을 같은 담당이 그리므로 장면 내 일관성이 유지된다.

### 검수자를 2명으로 두는 이유
한 명에게 "다 봐"라고 시키면 눈에 띄는 것만 보고 넘어간다. **보는 기준을 둘로 나누면** 각자 체크리스트를 끝까지 확인한다.
- 연속성 검수: "그림이 같은 세계인가" — 이미지 대 이미지 비교
- 연출 검수: "읽히는 만화인가" — 이야기와 페이지 단위 판단

## 4. 제작 흐름과 검수 관문

```
[1] 시나리오 ──▶ ◆G1 연출검수 ──▶ [사용자 승인]
[2] 아트 바이블·캐릭터 시트 ──▶ ◆G2 연속성검수 ──▶ [사용자 승인]   ← 여기서 그림체를 확정해야 뒤가 싸다
[3] 콘티 16컷 ──▶ ◆G3 연출검수
[4] 작화 A(1–8) ║ 작화 B(9–16)  병렬
        └─ 컷마다 ◆G4 연속성검수 ── 불합격 → 사유와 함께 작화 담당에게 반려 (컷당 최대 2회)
[5] 식자·조판 ──▶ ◆G5 연출검수 + 연속성검수 (페이지 전체)
[6] 팀장이 최종본과 검수 리포트 제출 ──▶ [사용자 최종 승인]
```

**재작업 규칙**
- 검수 결과는 `pass / fail` + 실패 사유 + 고칠 점(프롬프트 수정안)으로 남긴다.
- 같은 컷이 2번 반려되면 팀장이 원인을 판단한다: 프롬프트 문제 → 콘티 작가에게, 구도 자체가 무리 → 콘티 수정, 그래도 안 되면 사용자에게 보고.
- 통과된 컷은 잠근다. 나중에 다시 그리지 않는다.

## 7. Codex CLI로 돌릴 때 주의점

- **팀장은 스크립트 + 에이전트로 나눈다.** 순서·병렬 실행·재시도 횟수 같은 기계적 제어는 셸/파이썬 스크립트가 하고, "반려 사유를 보고 누구에게 보낼지" 같은 판단만 팀장 에이전트가 한다. 팀장 한 세션에 16컷 이미지를 다 쌓으면 컨텍스트가 넘친다.
- 각 직원은 `roles/<역할>.md` 프롬프트를 읽고 `codex exec`로 한 번 실행 후 종료한다. 공통 규칙(폴더 구조, 파일명, 덮어쓰기 금지)은 `AGENTS.md`에 둔다.
- 검수자는 이미지를 **보기만** 하도록 쓰기 권한을 `review/`로 제한한다.
- 작화 담당 호출 시 캐릭터 시트와 직전 컷을 참조 이미지로 같이 넘긴다.
- 대사는 이미지 모델에 넣지 않는다. 한글이 깨지고 고칠 수도 없다.

## 8. Claude 에이전트 / Codex 에이전트 배치

**원칙: Codex는 이미지 생성이 필요한 자리에만 둔다. 판단, 글, 검수, 코드 작업은 Claude가 맡는다.**
Codex 작화 담당은 판단하지 않고 지시서대로 그려서 저장만 한다. 무엇을 그릴지는 Claude 쪽에서 모두 정해서 넘긴다.

| 직원 | 엔진 | 이유 |
|---|---|---|
| 팀장 | **Claude** (Claude Code) | Bash로 `codex exec`를 호출해 작화 작업을 시키고, 결과 파일을 읽어 다음 단계를 정한다 |
| 시나리오 작가 | **Claude** | 글쓰기, 한국어 대사 |
| 콘티 작가 (+프롬프트 작성) | **Claude** | 컷별 구도와 **완성된 이미지 프롬프트**까지 작성해 작화 담당이 판단할 일을 없앤다 |
| 아트 디렉터 | **Claude** | 스타일 바이블과 캐릭터 고정 문구를 쓰고, 생성된 시트 후보 중 하나를 고른다. 시트 이미지 생성은 작화 A에게 시킨다 |
| 작화 A / B | **Codex** | 이미지 생성. 캐릭터 시트도 아트 디렉터 지시로 작화 A가 생성 |
| 식자·편집 | **Claude** | PIL/SVG 코드로 말풍선 합성, 조판 |
| 연속성 검수 | **Claude** (이미지 입력) | **다른 모델이 검수**하면 생성 모델의 버릇을 그대로 넘기지 않는다 |
| 연출·품질 검수 | **Claude** | 글과 페이지 흐름 판단 |

→ Claude 7명, Codex 2명.

### Claude ↔ Codex 주고받는 형식

Claude가 작업 지시서를 쓰고, Codex는 그 파일만 읽고 결과 2개를 남긴다.

```
jobs/p05_v2.json          # Claude(팀장)가 작성
{
  "panel": 5,
  "prompt": "<콘티 작가가 쓴 최종 프롬프트 + 캐릭터 고정 문구>",
  "references": ["bible/char_minji.png", "bible/bg_cafe.png", "panels/p04_v1.png"],
  "size": "1024x1024",
  "keep_empty": "top-right 30% (말풍선 자리, 글자 금지)",
  "fix_from_review": "왼손 손가락 6개 → 5개, 머리끈 색 빨강으로"
}

panels/p05_v2.png         # Codex가 생성
panels/p05_v2.meta.json   # Codex가 기록: 실제 사용한 프롬프트, 참조 이미지, 시드 등
```

Codex 작화 담당 규칙 (`roles/artist.md`에 넣을 내용):
- 지시서에 없는 것은 그리지 않는다. 프롬프트를 임의로 바꾸지 않는다.
- 글자, 말풍선, 효과음 금지.
- 기존 파일을 덮어쓰지 않고 버전 번호를 올린다.
- 생성 실패 시 `meta.json`에 오류를 남기고 종료한다 (재시도 판단은 팀장이 한다).

## 9. 사전 작화 전략: 무엇을 미리 그려 두나

**결론: 그림체만 후보를 그려 고르고, 캐릭터·배경은 "기준 1장"만 만든 뒤, 컷은 매번 참조 이미지를 붙여 새로 그린다.**
포즈·배경을 대량으로 미리 그려 오려 붙이는 방식은 쓰지 않는다.

| 방식 | 판단 | 이유 |
|---|---|---|
| A. 그림체 후보를 그려 고르기 | **그림체에만 사용** | 같은 장면을 그림체 3–4종으로 그려 사용자가 1개를 고른다. 이후 이 1장이 모든 작업의 기준이 된다 |
| B. 캐릭터 포즈·배경을 대량으로 그려 두고 골라서 수정 | **쓰지 않음** | 콘티가 요구하는 앵글·포즈와 맞는 그림이 거의 없어 결국 다시 그린다. 따로 그린 인물을 배경에 붙이면 조명·원근·선 굵기가 어긋난다. 미리 그린 그림 대부분이 버려진다 |
| C. 기존 만화를 참고로 주기 | **이미지로 주지 않고 말로 바꿔 쓴다** | 특정 작가의 원고를 넣어 따라 그리게 하면 저작권 문제가 생기고, 우리 캐릭터보다 참고작 캐릭터를 닮아 간다. "굵은 외곽선, 2톤 스크린톤, 큰 눈"처럼 특징만 글로 뽑아 바이블에 적는다 |

### 미리 만드는 것 (약 15장)
| 자산 | 수량 | 내용 |
|---|---|---|
| 그림체 테스트 | 3–4장 | 같은 장면 1개를 그림체별로. 1장 선택 → `bible/style_anchor.png` |
| 캐릭터 시트 | 주인공당 1–2장 | 한 장에 정면·측면·뒷모습 + 표정 4–6종. 조연은 정면 1장 |
| 배경 기준 | 장소당 1장 | 대본에 나오는 장소만. 인물 없는 넓은 샷 |

### 컷 생성 방식 (콘티에 `mode`로 지정)
- `generate` — 장면이 바뀌는 첫 컷. 그림체 기준 + 캐릭터 시트 + 배경 기준을 참조로 새로 그린다.
- `edit_prev` — 같은 장면의 연속 컷(예: 마주 앉아 대화하는 4컷). **직전 컷을 수정해서** 표정·손동작·카메라 거리만 바꾼다. 일관성이 가장 높고 빠르다.

### 바뀌는 제작 흐름
```
[2a] 그림체 테스트 3–4장 → 사용자 선택
[2b] 캐릭터 시트 (선택한 그림체를 참조) → 연속성 검수 → 사용자 승인
[2c] 배경 기준 (장소 수만큼)
[3]  콘티: 컷마다 mode(generate / edit_prev)와 참조 이미지 목록 지정
```

## 10. 직원별 업무 순서

각 직원의 상세 절차는 `roles/` 폴더에 있다. 이 파일을 그대로 각 에이전트의 역할 프롬프트로 쓴다.

| 파일 | 직원 | 엔진 |
|---|---|---|
| `roles/_common.md` | 모든 직원 공통 규칙 | — |
| `roles/00_director.md` | 팀장 | Claude |
| `roles/01_writer.md` | 시나리오 작가 | Claude |
| `roles/02_storyboard.md` | 콘티 작가 | Claude |
| `roles/03_art_director.md` | 아트 디렉터 | Claude |
| `roles/04_artist.md` | 작화 A / B | Codex |
| `roles/05_letterer.md` | 식자·편집 | Claude |
| `roles/06_continuity_reviewer.md` | 연속성 검수 | Claude |
| `roles/07_story_reviewer.md` | 연출·품질 검수 | Claude |

### 전체 진행표

```
단계  담당                        산출물                         관문
S0   팀장                         brief.md, production.json
S1   시나리오 작가                 script.md                     연출검수 → 사용자 승인
S2a  아트디렉터 → 작화A            그림체 후보 3–4장               사용자 선택
S2b  아트디렉터 → 작화A  ┐         캐릭터 시트                    연속성검수 → 사용자 승인
S2c  아트디렉터 → 작화B  ┘ 동시    배경 기준                      아트디렉터 선택
S3   콘티 작가                     storyboard.json               연출검수
S4   작화A ║ 작화B (장면 단위)     panels/                       컷마다 연속성검수 (반려 최대 2회)
S5   식자·편집                     lettered/, final/             연출검수 + 연속성검수
S6   팀장                          납품                           사용자 최종 승인
```

### 컷 하나의 상태 변화 (`production.json`)

```
todo → job_written → generated → reviewing ─ pass → passed(잠금) → lettered
                         ▲                   └ fail → job_written(v+1)
                         └── 2회 실패 시 팀장 판단: 콘티 수정 / 사용자 보고
```

`edit_prev` 컷은 직전 컷이 `passed`가 된 뒤에만 `job_written`으로 넘어간다.
