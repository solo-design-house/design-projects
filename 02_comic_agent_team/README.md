# 16컷 만화 제작 Agent 조직도

Claude는 이미지를 직접 만들지 못하므로 **이미지 생성은 Codex CLI 에이전트**가 맡는다.
각 "직원"은 역할 프롬프트를 가진 `codex exec` 실행 1회(또는 세션 1개)이고,
직원끼리는 대화하지 않고 **공유 폴더의 파일**로만 일을 주고받는다.

---

## 1. 결론 요약

| 질문 | 답 |
|---|---|
| 팀장이 필요한가? | **필요.** 단, 그림은 그리지 않고 일을 쪼개고, 상태를 기록하고, 재작업을 보내는 일만 한다. |
| 검수자가 필요한가? | **필요. 만든 사람과 다른 에이전트여야 한다.** 자기 그림을 자기가 검수하면 거의 다 통과시킨다. |
| 총 몇 명? | **권장 9명** (팀장 1 · 기획 2 · 아트 1 · 작화 2 · 마감 1 · 검수 2). 최소 5명, 확장 12명. |
| 가장 큰 위험 | ① 16컷 내내 캐릭터 얼굴·옷이 바뀌는 것 ② 이미지 모델이 한글 말풍선을 깨뜨리는 것 |
| 위험 대응 | ① 아트 디렉터가 먼저 **캐릭터 시트**를 만들고 모든 컷에 참조 이미지로 첨부 ② 대사는 그림에 넣지 않고 **식자 담당이 코드로 합성** |

## 3. 직원별 역할 정의

| # | 직원 | 인원 | 입력 | 하는 일 | 산출물 | 이미지 생성 |
|---|---|---|---|---|---|---|
| 0 | **팀장 (Director)** | 1 | 사용자 요청, `production.json` | 작업 순서 지정, 각 직원 호출, 검수 결과 보고 재작업 배정, 재시도 한도 관리, 사용자 승인 요청 | `production.json` (상태표), 작업 지시서 | ✗ |
| 1 | **시나리오 작가** | 1 | 주제·톤·대상 독자 | 로그라인 → 16컷 플롯. 기(1–4)·승(5–8)·전(9–12)·결(13–16) 4막 구조, 컷별 사건과 대사 | `script.md` | ✗ |
| 2 | **콘티 작가** | 1 | `script.md`, 스타일 바이블 | 컷마다 샷 크기, 앵글, 구도, 등장인물 위치, 표정·포즈, 배경, 말풍선 위치·여백 지정. 이미지 생성용 프롬프트 초안까지 작성 | `storyboard.json` (16개 항목) | ✗ |
| 3 | **아트 디렉터** | 1 | `script.md` | 그림체, 선, 채색, 팔레트 확정. 캐릭터별 **정면·측면·표정 시트** 생성. 배경 기준 이미지 생성. 모든 프롬프트에 고정으로 붙일 "캐릭터 고정 문구" 작성 | `bible/style.md`, `bible/char_*.png`, `bible/bg_*.png` | ✓ |
| 4 | **작화 담당 A·B** | 2 | `storyboard.json`, `bible/` | 맡은 컷을 생성. 캐릭터 시트를 반드시 참조 이미지로 첨부. **말풍선·글자는 그리지 않고** 콘티가 지정한 여백만 비워 둠 | `panels/pNN_vK.png` | ✓ |
| 5 | **식자·편집** | 1 | 통과된 컷, `storyboard.json` | 말풍선·대사·효과음을 코드(PIL/SVG)로 합성. 4×4 페이지(또는 세로 스크롤)로 조판, 칸 간격, 내보내기 | `lettered/`, `final/comic.png`, `final/comic.pdf` | ✗ (코드) |
| 6 | **연속성 검수** | 1 | 컷 이미지 + `bible/` | 얼굴·머리·옷·소품이 시트와 같은지, 앞뒤 컷의 좌우 위치(180도 규칙), 시간대·조명 일관성, 손가락 등 깨진 부분 | `review/continuity_*.json` | ✗ (이미지 보기만) |
| 7 | **연출·품질 검수** | 1 | 대본·콘티·완성본 | 대본·콘티 단계에서 이야기 흐름과 컷 수 검사. 완성본에서 읽는 순서, 말풍선이 얼굴을 가리는지, 오탈자, 마지막 컷의 펀치라인 | `review/story_*.json` | ✗ |

### 작화 담당을 2명으로 두는 이유
- 1명이면 16컷을 순서대로 그려 느리다.
- 4명 이상이면 사람마다 그림체가 벌어지고 API 동시 호출 한도에 걸리기 쉽다.
- **막 단위(1–8 / 9–16)로 나누면** 같은 장면의 연속 컷을 같은 담당이 그리므로 장면 내 일관성이 유지된다.

### 검수자를 2명으로 두는 이유
한 명에게 "다 봐"라고 시키면 눈에 띄는 것만 보고 넘어간다. **보는 기준을 둘로 나누면** 각자 체크리스트를 끝까지 확인한다.
- 연속성 검수: "그림이 같은 세계인가" — 이미지 대 이미지 비교
- 연출 검수: "읽히는 만화인가" — 이야기와 페이지 단위 판단

## 4. 제작 흐름과 검수 관문

```
[1] 시나리오 ──▶ ◆G1 연출검수 ──▶ [사용자 승인]
[2] 아트 바이블·캐릭터 시트 ──▶ ◆G2 연속성검수 ──▶ [사용자 승인]   ← 여기서 그림체를 확정해야 뒤가 싸다
[3] 콘티 16컷 ──▶ ◆G3 연출검수
[4] 작화 A(1–8) ║ 작화 B(9–16)  병렬
        └─ 컷마다 ◆G4 연속성검수 ── 불합격 → 사유와 함께 작화 담당에게 반려 (컷당 최대 2회)
[5] 식자·조판 ──▶ ◆G5 연출검수 + 연속성검수 (페이지 전체)
[6] 팀장이 최종본과 검수 리포트 제출 ──▶ [사용자 최종 승인]
```

**재작업 규칙**
- 검수 결과는 `pass / fail` + 실패 사유 + 고칠 점(프롬프트 수정안)으로 남긴다.
- 같은 컷이 2번 반려되면 팀장이 원인을 판단한다: 프롬프트 문제 → 콘티 작가에게, 구도 자체가 무리 → 콘티 수정, 그래도 안 되면 사용자에게 보고.
- 통과된 컷은 잠근다. 나중에 다시 그리지 않는다.

## 5. 공유 폴더 구조

```
comic/
├── production.json        # 팀장이 관리하는 상태표 (컷별 단계·버전·반려 횟수)
├── brief.md               # 사용자 요청
├── script.md
├── storyboard.json
├── bible/
│   ├── style.md           # 그림체·팔레트·캐릭터 고정 문구
│   ├── char_<이름>.png
│   └── bg_<장소>.png
├── panels/p01_v1.png ...  # 작화 원본 (버전 누적, 덮어쓰기 금지)
├── lettered/p01.png ...
├── review/                # 검수 리포트
└── final/
```

`storyboard.json` 한 항목 예:
```json
{
  "panel": 5,
  "act": "승",
  "shot": "미디엄 샷, 눈높이",
  "characters": [{"id": "minji", "pos": "left", "expression": "놀람", "pose": "휴대폰을 떨어뜨림"}],
  "background": "bg_cafe",
  "dialogue": [{"speaker": "minji", "text": "설마…", "bubble": "top-right"}],
  "empty_area": "top-right 30%",
  "prompt": "..."
}
```

## 7. Codex CLI로 돌릴 때 주의점

- **팀장은 스크립트 + 에이전트로 나눈다.** 순서·병렬 실행·재시도 횟수 같은 기계적 제어는 셸/파이썬 스크립트가 하고, "반려 사유를 보고 누구에게 보낼지" 같은 판단만 팀장 에이전트가 한다. 팀장 한 세션에 16컷 이미지를 다 쌓으면 컨텍스트가 넘친다.
- 각 직원은 `roles/<역할>.md` 프롬프트를 읽고 `codex exec`로 한 번 실행 후 종료한다. 공통 규칙(폴더 구조, 파일명, 덮어쓰기 금지)은 `AGENTS.md`에 둔다.
- 검수자는 이미지를 **보기만** 하도록 쓰기 권한을 `review/`로 제한한다.
- 작화 담당 호출 시 캐릭터 시트와 직전 컷을 참조 이미지로 같이 넘긴다.
- 대사는 이미지 모델에 넣지 않는다. 한글이 깨지고 고칠 수도 없다.
